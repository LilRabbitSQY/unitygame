## 目标与范围

负责`Scripts/Combat/`的规则（不含`BattleView.cs`、`BattleBoardPresentation.cs`）、新增匹配模块、`Resources/Battle/`、战斗导入与纯逻辑测试。可改`Tests/Offline/`现有战斗套件及其`sources.json`；不要把Part 1测试目录纳入自己的文件改写。

`GameManager`、商品价格/库存、存档归Part 1；所有Unity场景、Bootstrap、表现代码、UI和共享asmdef归Part 3。当前`BattleView`固定随机种子和职责拆分问题通过接口说明交Part 3修改，不能两方同时编辑。

## B01 — 修复已确认的数值问题

- [ ] **盾反：** 统一技能伤害结算路径，考虑防御、易伤、减伤、庇护和规则中的暴击。敌方防御900、受击防御353、易伤20%、庇护10%，非暴击619，不能直接扣900。同步检查我方反击路径及其他技能的伤害类型声明。
- [ ] **保底：** 完整伤害公式结算后处理负值保底，攻击100、防御500、暴击应回退5，不能保底后再乘到8。保留零伤害为零、正值不足5%不强抬的现行文档规则。
- [ ] **回退：** 前进与回退共用最终移速；基础1、减速20%时一秒均移动0.8格，只改变方向。
- [ ] **多来源减速：** 区分施加者，两个开源学霸独立成功触发应合计−40%；同一来源刷新。不改变明确写“不可叠加”的卷王减防。
- [ ] 固化以上复现为仓库生产源码回归测试，附文档原表行，不依赖`/tmp`文件。
- [ ] 梳理DamageDirect用途；灼烧/中毒等明确直接扣HP者保持明确类型，不把全部DOT强制改成普通攻击公式。
- [ ] 冰冻停普攻/SP、技能期间升级影响已施加增益属于D11，不在修bug时静默决定。

**验收：** 四个独立预期用例通过；已有1497示例、32技能、护盾/治疗/DOT/追击不递归等不回归。

## B02 — 提供可复用的战斗会话接口

- [ ] 接受Part 1的`BattleStartContext`，适配已有BattleConfiguration/Simulation，不读取全局GameManager，不扣背包或改GPA。

- [ ] 输出只读单位/费用/波次状态与攻击、弹道、命中、技能、倒地、升级、结局事件，包含实体ID、动作序号、等级和必要位置数据，供Part 3做动画/音效。
- [ ] 模拟30Hz仍独立于渲染；只让一个Unity宿主调用Tick。订阅/销毁/重试时事件不能重复派发。
- [ ] 结束生成一次`BattleOutcome`，将现Report映射过去；不在结束回调和UI中各提交一次。是否弃局由明确原因字段区分。
- [ ] 给Part 3最小调用样例和旧BattleView迁移步骤，先适配已有页面再接同学UI。

**验收：** 同一个输入种子/配置/命令产生相同结果；不同渲染帧率不改变战斗；结束/销毁后无额外数值变动。
