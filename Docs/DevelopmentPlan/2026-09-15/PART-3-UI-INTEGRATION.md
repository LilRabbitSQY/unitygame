# Part 3：UI、素材、音频与整合验收

先读[总计划](README.md)，尤其文件归属和M0。你负责真实页面和整合，不在页面脚本里复制Part 1/2的业务规则。

## 目标与范围

把同学已制作的页面、已有美术与两个功能模块接成真正可玩的完整游戏。页面布局优先沿用同学工程/正式稿；已有控件替换素材，缺失功能按该风格补齐。不要重新生成封面或另做一套主题。

负责全部`Scripts/UI/`、`Scripts/Audio/`、`Combat/BattleView.cs`、`Combat/BattleBoardPresentation.cs`、`Battle/BattleSceneBootstrap.cs`、`Core/SceneLoader.cs`、Scenes/Prefabs、视觉音频Resources、Packages/ProjectSettings/asmdef、`Editor/DemoSetup.cs`、Unity集成测试与发布工具。NPC/玩家资源数据归Part 1，`Resources/Battle/`规则数据归Part 2，不能整包覆盖。

- [ ] 对方若也改GameManager/战斗/商店，将对应差异交归属方合并；保留其页面和有效功能，不只拷图片导致原交互丢失。
- [ ] 补读正式Figma/嵌入图的页面结构和道具使用流程，记录具体页面/节点/版本。若资源尚未交付，明确缺失清单，可继续绑定与已有页面联调，正式视觉验收保持未完成。
- [ ] 建立素材清单：现有45张原图、三首BGM、三个未接入短音效；另外列出UI背景按钮、地面/高台地块、敌方表现、逐棋子攻击/命中特效、角色表情差分的已有/待交付状态。
- [ ] 检查10张白底头像适合头像槽，不直接当透明全身立绘；气泡聪明水烘焙背景不能靠导入设定变透明。需要补图时记录原素材问题，不自行涂改/重绘冒充交付。
- [ ] 决定敌我是否复用棋子图以及区分方式并记录；正式三级表现、情绪差分不能用不存在的资源标记完成。
- [ ] 所有Unity资产保留`.meta`和GUID，新的映射以稳定ID关联；清理丢失引用需定位真实使用点，不能批量删除来源不明资源。

**交付：** 原页面来源、功能差异列表、素材使用/缺口清单、截图基准和外部交付状态。可写入本部分交接文档，避免把新资源盘点与旧导入报告混淆。

## C02 — 新游戏、继续、设置和基础导航

- [ ] 接Part 1的新游戏、存档列表、读档、坏档提示、覆盖确认；新游戏入口不依赖已有档才出现。读档显示天数/阶段等元信息。
- [ ] 主页使用同学四入口（开始、继续、设置、退出）；退出/ESC行为与弹窗优先级一致。关窗口与战斗弃局交给统一服务，不能自己额外扣分。
- [ ] 设置分辨率、窗口模式、BGM和音效音量，应用Part 1的持久化设置；不改用户系统音量。未提供的目标平台功能不显示为可用。
- [ ] 接世界观、预约/编队/部署等必要引导，避免玩家进入后不知道下一步；旧人格流程是否保留按D15，不让旧问答阻断最新流程。
- [ ] 统一个人界面与战斗弹窗的ESC、返回、确认/取消、焦点和遮罩规则；点击被遮挡时不能穿透操作。
- [ ] 所有实际场景/面板进入构建，补齐AVG等入口；移除Schedule直接绕过未完成AVG的正式路径。

**验收：** 冷启动→新游戏和已有档→继续均可用；设置重启保留；返回和退出不会重复结算或落入不存在场景。

## C03 — 日程、聊天与每次行动结算

- [ ] 按原页面/正式稿绑定手机日程：三时段、地点、NPC、确认预约、已锁定状态、当前时段。
- [ ] 聊天HUD显示时间/地点/NPC/剩余行动，NPC先发言；左右消息、输入框、三提示、发送、流式输出/等待/失败重试均连接Part 1服务。
- [ ] 中文输入法组合输入时不误发送；长文本、空文本、换行、快速连点处理正确。若目标含移动端，单独验证虚拟键盘和安全区。
- [ ] 只显示服务返回的合法文本/情感，不把模型消息作为UI指令；切换对话或页面后不接收旧请求的迟到回调。
- [ ] 单次行动结束弹出真实好感变化、额度上限和道具获取；确认后由状态机推进，不能UI自行加分/加物。
- [ ] 老师/院长客串和情绪头像按内容映射；系统保持引导身份，不误加好感或礼物。

**验收：** 三段实际对话后才能进编队；断网/重试/切页/中文输入可恢复，既不丢失已结算收益也不重复发放。

## C04 — 抽签、编队与战斗接入

- [ ] 显示NPC抽取过程与最终对手、双方GPA、先后手原因、可选/已选阵容和锁定状态。界面读Part 2状态，抽签动画不能偷偷重抽结果。
- [ ] 根据D01接一种正式选人交互；提示满员/非法选择/等待NPC，补给界面依据Part 1库存状态。
- [ ] 拆开当前BattleView的BuildUI、输入、Tick和结算职责：一个Unity宿主创建/驱动Part 2会话，页面只绑定状态和命令。旧BattleManager/EnemySpawner等不能同时启用。
- [ ] 将按对象名称寻找Canvas/HUD/地图的脆弱依赖改为明确绑定点；保留现有GameArt和映射。必要适配同学prefab，不重新创建整屏覆盖其页面。
- [ ] 按day/levelId取Part 2配置，取消固定Level1和固定731种子的正式入口；不擅自保留“保护值=min(GPA)”等旧耦合，按定稿参数接入。
- [ ] 真正支持卡牌拖拽/点击、合法格提示、朝向、范围、费用不足、升级、撤回、倒地/再部署、暂停、菜单和结果。遵守最新版不提供二倍速按钮要求。
- [ ] BattleOutcome只提交给Part 1唯一入口；结果页显示服务返回的GPA分项、NPC变化、连胜、排名和物品，不在文案中硬编码胜利+5或按漏怪扣GPA。
- [ ] 多次进出战斗释放订阅、图像和临时对象；UI没有第二个模拟器或重复音乐服务。

**验收：** 正常窗口内的真实点击/拖动可命中，两个先后手都能开战；UI变化不改变模拟结果；重试和退出不会二次结算。

## C05 — 美术、动画、音效和显示质量

- [ ] 角色/道具/棋子使用现有原素材和正式交付；同学页面缺素材时保持清单，不能以新绘封面代替原设计。
- [ ] 逐棋子接入攻击动作及发射/命中特效；等级1/2/3用定稿的大小、等级图标、攻击特效区分。每类动作挂Part 2事件，动画不能决定真实伤害。
- [ ] 接八类情感标签到相应头像差分，缺差分用清楚的开发状态记录，最终要么补齐要么取得明确的范围调整，不能一张中性头像算全部完成。
- [ ] 保留3首BGM循环、场景路由和淡入淡出；新增按钮、对话、抽签、棋子攻击、胜利、失败六类音效。现有三个短音效先试听标用途，缺的补交付，不把BGM当音效。
- [ ] 设置音效音量/并发上限与重复触发控制；长战斗避免每个攻击无限叠音或每次进场重复AudioListener。
- [ ] 按1920×1080基准及目标窗口尺寸检查中文字体、文字溢出、背包/图鉴滚动、卡牌遮挡、提示层级、血量/护盾/SP和敌人/GPA图标；处理当前Hint与HUD重叠。
- [ ] 记录导入压缩、PPU/裁剪、音频流式设置与使用场景，保留原始资源来源，不靠删除白底改变授权素材原图。

**验收：** 有真实Unity截图/音频观察记录及对应资源；逐项核对素材清单，无占位色点代替正式要求却宣称完成。
