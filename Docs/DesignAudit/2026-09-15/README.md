## 需求内部冲突及需要定稿的项目

这些项目不宜直接判成程序错误，应先确定哪张表为准：

1. **请假条**：关卡140行/UI68行是“首波延迟3秒”；包装306行是“下一波延迟15秒”（该段标题称效果示例可改）。当前采用前者。
2. **院长推荐信**：关卡141行/UI69行、包装502行是胜利额外+1 GPA；包装311行写+0.5。当前采用+1。
3. **选人方式**：文案34行写“轮流”，94行写“先手选择一半、后手自动拿剩下的”。当前至少缺少共同要求的GPA先后手/NPC决策；是否必须逐手交替，需要统一。
4. **失败边界**：文案23行/包装684行为GPA小于0，当前GPA被截到0且0即结束。需明确0是否允许继续，以及购物花光GPA是否也结束游戏。
5. **经济用途**：关卡81行提学分币结算，但道具价格明确用GPA。当前有金币累计、商店用GPA，金币未构成消费闭环；不应擅自把表格改读成金币购买。
6. **道具使用交互**：关卡156行指定以Figma为准，当前自动携带/消耗；未读完整Figma前，暂标“实现方式待确认”，不认定自动携带就是正确交互。
7. **关卡及战斗默认参数**：当前地图、初始COST20、上限99、每秒恢复1、10点保护、10部署上限、15秒重部署、基础弹速8等含实现默认值；原表未完整定稿的部分见 `Docs/Battle/README.md` 第5节。
8. **美术稿验收**：正式主菜单截图所对应工程不在当前工作区（项目README已有记录）；嵌入图与Figma未完成逐图对照，不能给“UI一致”的结论。
